В app/ находятся только gui.py, simulator.py и main.py; физические модули находятся в корне проекта. Команды ниже выполняйте из корня проекта.

# Симулятор фазового ДОЭ

Локальное приложение: одна фазовая маска 128×128 → четыре распределения
интенсивности на расстояниях 24,1 / 25,3 / 26,5 / 27,7 мм.
На этом этапе нет нейросети, обучения и подбора фазы. Случайная маска обычно
даёт спекловые распределения, а не четыре осмысленных целевых изображения.

## Запуск

В терминале из папки проекта (проверено на Python 3.14, Windows):

```powershell
python -m pip install -r requirements.txt
python main.py
```

GUI использует встроенный Tkinter и Pillow; кроме NumPy и Pillow зависимости
не добавлены. Tkinter входит в стандартную установку Python для Windows.
Если `from PIL import Image` не работает, проверьте, что интерпретатор IDE тот
же, в котором выполнена установка: `python -c "import sys; print(sys.executable)"`.
В PyCharm запускайте `main.py` с рабочей папкой проекта.

Для этой Windows-среды добавлена инициализация штатной DLL Tcl до импорта
`tkinter`: без неё Tcl не видел существующий `init.tcl`. Загрузчик использует
только DLL из выбранной установки Python, не меняет системные файлы и
переменные окружения. Запускайте приложение новым процессом через `main.py`;
уже неудачно инициализированный Tcl в интерактивной консоли следует перезапустить.

1. Введите неотрицательный целый seed или оставьте поле пустым.
2. Нажмите «Сгенерировать случайную матрицу» либо загрузите фазовый PNG.
3. Нажмите «Рассчитать дифракцию» — появятся четыре экрана из одной маски.
4. Нажмите «Сохранить результаты» и выберите родительскую папку.
   В ней создаётся отдельная папка запуска без перезаписи старых результатов.

Загружается только статический одноканальный 8-битный PNG 128×128 (режим L).
RGB, RGBA, палитра, 16 бит и другие размеры отклоняются без преобразования.
Значения 0 и 255 соответствуют −π и +π; это циклически эквивалентные фазы.
PNG не может точно представить нулевую фазу: она лежит между двумя уровнями.

## Что рассчитывается

Все длины в метрах. λ = 532e-9; Δu = Δv = 10e-6; N = 128.
Размер ДОЭ NΔu = 1,28 мм; освещение плоской волной с амплитудой A=1.
Интенсивность относительная, без калибровки в Вт/м².

Для массива `H[row, col]` столбцы соответствуют u/x, строки — v/y:
`u=(col-N//2)*Δu`, `v=(row-N//2)*Δv`. Это соглашение `meshgrid(indexing="xy")`;
положительное y направлено вниз на изображении GUI.

```text
H = exp(i*phase)
G = H * exp(i*pi*(u²+v²)/(λ*z))
F = fftshift(fft2(ifftshift(G)))
Δx = Δy = λ*z/(N*Δu)
x = (col-N//2)*Δx; y = (row-N//2)*Δy
K = exp(i*k*z)/(i*λ*z) * exp(i*pi*(x²+y²)/(λ*z)) * F * Δu²
I = abs(K)²
```

На каждую плоскость выполняется один 2D FFT. Входное поле H общее для всех
четырёх плоскостей. Ни комплексное поле, ни физическая интенсивность внутри
расчёта не нормируются. Вспомогательная матрица G не является отдельным экраном.

| z, мм | Δx, мкм | Ширина NΔx, мм |
| --- | --- | --- |
| 24,1 | 10,0165625 | 1,28212 |
| 25,3 | 10,5153125 | 1,34596 |
| 26,5 | 11,0140625 | 1,40980 |
| 27,7 | 11,5128125 | 1,47364 |

Ширина области означает N шагов. Расстояние между крайними центрами равно
(N−1)Δx; первая координата −64Δx, последняя +63Δx.
Изображения интерфейса имеют одинаковые размеры в пикселях, но разные физические
размеры областей. GUI показывает это под каждым экраном.

## Модули и совместимость

- `mathlib.py`: единственная рабочая реализация формулы Френеля;
  `slm_field_matrix` создаёт H, `fresnel_field_matrix` возвращает K,
  `reconstruct_intensity(field, z)` возвращает I, `output_pixel_pitch(z)` — шаг.
  Существующие скалярные функции и их сигнатуры сохранены.
- `simulator.py`: `generate_random_phase(seed)`, `phase_to_field(phase)`,
  `simulate(phase, seed, source)` и `reconstruct_all(phase)`; оркестрация и экспорт.
  `simulate` возвращает снимок `SimulationResult` с исходной фазой, общим H,
  четырьмя K и четырьмя I. Входная фаза не изменяется; массивы снимка read-only.
- `pictures.py`: строгая загрузка/кодировка фазы, существующие классы
  `InputPictures`/`OutputPictures` и нормировка PNG.
- `gui.py`: только управление, отображение и вызовы backend; `main.py` — запуск.

Важно: старый `mathlib.reconstruct_intensity` принимает **поле H**, не фазу.
Вызов для фазы: `reconstruct_intensity(phase_to_field(phase), z)`.
Также сохранена скалярная сигнатура `fresnel_propagate(fft_value,x,y,z)`;
для всего поля используется `fresnel_field_matrix(field,z)`.
Граница между GUI и backend позволяет позже заменить вычислительный модуль
на PyTorch; текущий NumPy backend не поддерживает автоматические градиенты.

## Отображение и экспорт

Для каждого PNG и экранного превью отдельно:
`pixel = round(255*I/max(I))`; нулевой массив остаётся чёрным.
Нет вычитания минимума, гаммы, логарифмирования и нормировки внутри физики.
Такое отображение скрывает различия абсолютной яркости между экранами,
поэтому интерфейс также показывает исходный максимум каждой интенсивности.

В новой папке запуска:

- `doe.png` — фаза по фиксированной шкале `round(255*(phase+π)/(2π))`.
- `phase_radians.npy` — исходная фаза float64 без потери точности.
- `1.png` … `4.png` — нормированные превью, как в GUI.
- `1.npy` … `4.npy` — исходные ненормированные интенсивности float64, точно как
  в GUI. Загрузка: `np.load(path, allow_pickle=False)`.
- `metadata.json` — параметры СИ, координаты, seed, источник, шаги и размеры,
  правила нормировки, исходные максимумы, дискретная мощность и ограничения.
- `quantized/1.png` … `quantized/4.png` и соответствующие `.npy` — дополнительные
  восстановления **из фактически сохранённого и повторно загруженного `doe.png`**.

Две версии нужны, поскольку кодирование случайной float64 фазы в PNG вносит
квантование: шаг 2π/255 ≈ 0,02464 рад, максимальная ошибка π/255 ≈ 0,01232 рад.
Основные NPY сохраняют точный расчёт GUI; папка `quantized` позволяет проверить
работу экспортированного 8-битного ДОЭ. Для дальнейшей сдачи результата из
PNG-маски следует использовать именно `quantized`.
При загруженной PNG-фазе обе версии численно совпадают.
Пустой seed означает случайный выбор энтропии; точная фаза всё равно сохраняется
в NPY. Seed фиксирует генерацию NumPy в проверенном окружении requirements.txt.
При ошибке записи частичная новая папка остаётся для диагностики; старые
файлы не перезаписываются, об ошибке сообщается в интерфейсе.

```powershell
python -B -m unittest discover -s tests -v
python check_sampling.py --output sampling_report.json
```

Тесты проверяют существующие функции и форматы, нулевую и случайную фазу,
инвариантность интенсивности к глобальной фазе, линейный наклон и знак сдвига,
энергию с учётом площади пикселей, шаги СИ, отбрасывание неверных расстояний,
воспроизводимость seed, PNG-квантование, экспорт и сохранность исходных данных.
Скрипт `check_sampling.py` отдельно оценивает чувствительность к квадратуре.
Проверка в текущем Windows-окружении: **66 тестов пройдено**, включая четыре
сквозных теста настоящих Tk-виджетов (диалоги выбора файлов заменены тестовыми).
Проверены переходы состояния, расчёт, экспорт NPY без потерь, загрузка PNG,
отмена сохранения и сохранность текущей фазы при ошибке seed или RGB-файле.

## Ограничения численной и физической модели

Рабочая модель — скалярное параксиальное приближение Френеля с суммированием
по центрам пикселей. Не учитываются заполнение пикселя, его рельеф, интеграл
внутри пикселя, поляризация, реальные аберрации, калибровка ПВМС и профиль лазера.

Ориентир дискретизации входной квадратичной фазы:
`zcrit = N*Δu²/λ ≈ 24,06015 мм`. Первая плоскость почти на этой границе.
Максимальные соседние приращения входной квадратичной фазы: приблизительно
3,112; 2,964; 2,830; 2,707 рад. Случайная фаза не ограничена по пространственному
спектру, поэтому выполнение этого условия для chirp не исключает алиасинг H*chirp.
Соседние приращения выходной фазы в трёх последних плоскостях превышают π;
этот множитель сокращается при вычислении |K|², но влияет на интерпретацию
комплексного поля и его дальнейшее распространение.

Диагностика `check_sampling.py` сравнивает пять точек каждого экрана:
центр, ближнюю к центру, внутреннюю и два угла. FFT совпадает с прямой
суммой по центрам с относительной L2-ошибкой комплексного поля менее 8e-14.
Это проверка **дискретной формулы**, а не доказательство точности для реального ДОЭ.

Независимая квадратура принимает постоянное H внутри квадратного пикселя
с заполнением 100% и границами «центр ± Δu/2». При интегрировании ядра
с 128 подшагами на ось отличие FFT от этой модели по пяти точкам существенно:

| Фаза | 24,1 мм | 25,3 мм | 26,5 мм | 27,7 мм |
| --- | --- | --- | --- | --- |
| Нулевая | 0,570 | 0,259 | 0,133 | 0,080 |
| Случайная, seed 42 | 1,129 | 0,466 | 0,918 | 0,995 |

Это относительная L2-ошибка **комплексного поля**, не ошибка интенсивности или
SSIM и не оценка всего изображения. Изменение опорной квадратуры при переходе
с 64 до 128 подшагов менее 9,2e-5; это эмпирическая сходимость, не строгая граница.
Диагностика не подменяет обязательный одно-FFT расчёт в приложении.

Сохранение дискретной энергии следует из равенства Парсеваля и проверяет
масштаб FFT, но само по себе не подтверждает непрерывную физическую модель.
Оценка первого отброшенного члена параксиальной фазы на наиболее удалённых
точках апертуры и экрана составляет порядка 1 рад. Сравнение с непараксиальным
распространением не выполнено. Полная оптическая точность для заданных
параметров, особенно на краях и для произвольных случайных масок, **не подтверждена**.


## Загрузка фаз из TXT

В интерфейсе нажмите «Загрузить фазы TXT». После выбора файла автоматически
рассчитываются четыре плоскости через ту же физическую модель Френеля.
TXT должен содержать 128 строк по 128 чисел в радианах, от −π до π.
Пробелы, табуляции, запятые и `;` допустимы как разделители, десятичный знак —
точка; научная запись `1.2e-3` допустима. Комментарии начинаются с `#`.
Числа не интерпретируются как пиксели 0..255, не нормируются и не квантуются.
NaN, бесконечности, неверные размеры и выход за диапазон отклоняются.
При ошибке загрузки предыдущая маска и результаты остаются доступны.

Пример создания входного файла и программного расчёта:

```python
import numpy as np
from simulator import simulate_phase_txt

phase = np.zeros((128, 128), dtype=np.float64)
np.savetxt("phase.txt", phase, fmt="%.17g")
result = simulate_phase_txt("phase.txt")
print(result.intensities.shape)  # (4, 128, 128), без нормировки
```

`pictures.load_phase_txt(path)` возвращает только фазовую матрицу;
`simulator.simulate_phase_txt(path)` возвращает фазу, поле H, четыре поля K
и четыре интенсивности через существующий `simulate`, без дублирования физики.

TXT: погрешность записи у границ ±π до 1e-9 рад исправляется до точной границы; более крупный выход за диапазон отклоняется.
