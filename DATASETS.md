# Открытые датасеты для тестирования синтеза ДОЭ

Проверено 6 ноября 2026 года. Требования проекта: четыре целевых изображения PNG, 128×128, 8 бит, один канал; одна общая фазовая маска и четыре плоскости восстановления.

Рекомендую начать с **Fashion-MNIST**, добавить **Omniglot** для штрихов и **Oxford-IIIT Pet** для фотографий. Это выбор тестовых данных, а не требование ТЗ и не подтверждение достижимого качества реконструкций.

Число изображений Kuzushiji-Kanji приведено с учётом [исправления авторов от 31 мая 2024 года](https://codh.rois.ac.jp/kmnist/index.html.en): 140 424, а не встречающееся в старых описаниях 140 426.

Увеличение изображений 28×28 или 64×64 не добавляет исходных деталей. Поэтому результаты на Fashion-MNIST/KMNIST следует дополнять проверками на Omniglot и уменьшенных фотографиях. Указанная пригодность — вывод по содержанию наборов; сравнительный эксперимент по качеству ДОЭ ещё не проведён.

## Дополнительный вариант с ограниченными условиями

[DIV2K](https://data.vision.ee.ethz.ch/cvl/DIV2K/) содержит разнообразные RGB фотографии примерно 2K: 800 train, 100 validation, 100 test. Для нашей задачи достаточно общедоступных HR train/validation изображений, преобразованных в grayscale 128×128. Пары низкого и высокого разрешения не нужны.

**У авторов указано только академическое исследовательское использование.** Это доступный исследовательский набор, но его не следует приравнивать к наборам с MIT или CC BY-SA. Для основного набора фотографий здесь предпочтительнее Oxford-IIIT Pet с явно указанной CC BY-SA 4.0.

## Как подготовить входы для существующего кода

Следующие правила — предлагаемый протокол тестирования, а не дополнительные условия ТЗ.

1. Сохранить исходный архив отдельно. Записать URL, версию/дату, SHA-256, лицензию и индексы либо имена выбранных изображений.
2. Для квадратных изображений использовать изменение размера до 128×128. Для фотографий разных пропорций сначала сделать центральную квадратную обрезку. Если обрезка удаляет важный объект, использовать отдельно описанный вариант с полями и фиксированным цветом фона.
3. Явно вызвать преобразование в режим Pillow `L`. Для увеличения предлагается `BILINEAR`, для уменьшения фотографий — `LANCZOS`. Сохранить результат именно как 8-битный PNG: палитровый PNG, режим `1` и RGB существующий загрузчик отвергает.
4. Полярность выбрать заранее. Например, для Omniglot можно инвертировать изображение, чтобы получить светлый символ на тёмном фоне; такую инверсию нужно записать в описание подготовки и применять последовательно.
5. Хранить одну четвёрку в отдельной папке с файлами `01.png`, `02.png`, `03.png`, `04.png`. `InputPictures.load()` сортирует имена и требует ровно четыре файла. Файл описания, лицензию и контрольные суммы хранить вне этой папки: даже дополнительный `.txt` нарушит проверку числа файлов.
6. Зафиксировать соответствие: `01.png` → 24,1 мм; `02.png` → 25,3 мм; `03.png` → 26,5 мм; `04.png` → 27,7 мм. Четвёрка служит одним входом для синтеза одной общей фазовой маски.
7. Для обычных тестовых изображений предлагается считать `pixel / 255` заданной нормированной интенсивностью. Это явно выбранное допущение без обратного гамма-преобразования; значения RGB/grayscale фотографии не являются измерением оптической интенсивности. `InputPictures.normalize()` уже выполняет деление на 255 и возвращает `float32`.

Предлагаемая структура, которую можно создать при подготовке данных:

```text
data/
  manifest.json
  licenses/
  test/
    fashion_0001/
      01.png
      02.png
      03.png
      04.png
    omniglot_0001/
      01.png
      02.png
      03.png
      04.png
```

В `manifest.json` полезно сохранять ID четвёрки, source ID каждого изображения, исходный split, расстояние, обрезку, интерполяцию, инверсию, версии библиотек и seed. Для начала предлагается `seed=42`.

## Как сформировать тестовую выборку

Для первых проверок достаточно одной фиксированной четвёрки Fashion-MNIST. Для оценки качества предлагается по 25 четвёрок из Fashion-MNIST, Omniglot и Oxford-IIIT Pet: всего 75 запусков и 300 целевых изображений. Этот объём выбран для удобства первого эксперимента и не означает статистически достаточного размера выборки.

Если появится обучение общей модели, сначала разделить исходные изображения на train/validation/test, затем составлять четвёрки только внутри своего раздела. Все обрезки и преобразования одного исходного изображения должны оставаться в одном разделе. Для Fashion-MNIST и KMNIST сохранить официальный test; validation выделить из train. Для Omniglot можно использовать background для train/validation и evaluation для test. Для Oxford-IIIT Pet использовать официальный trainval/test, выделив validation из trainval.

Включить четвёрки с разными объектами, похожими объектами и разной заполненностью кадра. Для проверки зависимости от плоскости добавить перестановки одной четвёрки; результаты считать связанными наблюдениями, а не независимыми изображениями. Если нейросеть обучается отдельно на каждой четвёрке, явно описать такой режим: метрики после подгонки не являются проверкой обобщения на невидимые входы.

Дополнительно полезны генерируемые тесты: нулевое и постоянное поле изображения, одиночная точка, линии, кольцо и решётка. Это синтетические тесты, не открытый датасет и не исходные изображения кейса. У постоянного изображения Pearson не определён из-за нулевой дисперсии; следует проверить явную обработку этого случая.

## Что эти данные позволяют проверить

Наборы дают целевые изображения для загрузки и последующего синтеза. Готовые эталонные фазовые маски не обязательны, если обучение построено на сравнении рассчитанной по физической модели интенсивности с целями. Это возможное решение обучения; ТЗ не предписывает конкретную архитектуру или схему обучения.

Такие изображения сами по себе не подтверждают корректность одно-FFT модели Френеля. Для неё нужны отдельные проверки дискретизации, физических единиц, градиентов и распространения. Параметры проекта остаются: λ=532 нм, шаг ПВМС 10 мкм, N=128. Для одно-FFT схемы шаг выходной плоскости `Δx_out = λz / (N·Δx_in)` составляет приблизительно 10,017 / 10,515 / 11,014 / 11,513 мкм. Одинаковый размер массива 128×128 не означает одинаковый физический размер изображений на четырёх расстояниях. Эти значения рассчитаны из ТЗ, а не взяты из датасетов.

Pearson и SSIM впоследствии нужно считать для каждой плоскости отдельно после загрузки сохранённого 8-битного `doe.png` и физического восстановления. До сравнения необходимо зафиксировать нормировку интенсивности и `data_range` для SSIM. Предобработанный PNG служит целевым изображением; нельзя незаметно менять его масштаб, сдвиг или контраст после получения реконструкции для улучшения метрик.
