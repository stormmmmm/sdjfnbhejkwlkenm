# PHASE — веб-сервер без регистрации

## Запуск в PyCharm

В терминале проекта:

```powershell
python -m pip install -r requirements_web.txt
python run_web.py
```

Откройте http://127.0.0.1:8000. Можно также запускать `web_app.py` кнопкой Run, без параметров. Старый настольный запуск `main.py` сохранён.

Для доступа с других устройств вашей сети: `python run_web.py --host 0.0.0.0 --port 8000`, затем адрес компьютера в этой сети и порт 8000. По умолчанию сервер слушает только localhost. Публичного размещения в этой задаче не выполнялось.

## Что работает

- Четыре пользовательских фото → одна общая фазовая маска 128×128.
- Отдельный режим: загрузка готовой фазы PNG или TXT и расчёт дифракции существующим `simulator.simulate`.
- Фоновая очередь, два вычислительных потока по умолчанию. Количество: переменная окружения `DOE_WORKERS` (1–8).
- WebSocket `/ws/jobs/{id}`: состояние, прогресс, результат и ошибки. При обрыве соединения страница переходит на HTTP-опрос. Отсоединение браузера не отменяет расчёт; предусмотрена отдельная кнопка остановки.
- Скачивание общей матрицы TXT (128 строк × 128 значений в радианах), 8-битной фазовой маски, четырёх восстановлений, метрик и ZIP с исходными данными.
- Без регистрации и аккаунтов. Ссылка с длинным случайным ID является доступом к задаче; не передавайте её, если хотите сохранить результат приватным. Списка чужих задач нет.

## Устройство сервера

FastAPI + Uvicorn, ОДИН процесс ASGI, отдельный `ThreadPoolExecutor`. HTTP/WebSocket-цикл не выполняет расчёт модели. Тяжёлая обработка идёт в выделенных потоках; NumPy освобождает GIL для значительной части матричных операций. Это не обещание линейного ускорения Python-кода. Число потоков BLAS по умолчанию ограничено единицей для предотвращения вложенной перегрузки.

Задачи и результаты изолированы: свой ID, свой массив входов и своя изменяемая копия весов на каждую задачу. Веса на диске не перезаписываются. Ограничено 24 задачи в памяти, включая очередь и завершённые результаты. При заполнении сначала вытесняется самый старый готовый результат; если все задачи активны, сервер отвечает 503. Готовые результаты доступны до часа или до вытеснения/перезапуска. Файлы исходных фотографий не сохраняются постоянно на диске; временный экспорт удаляется после упаковки. Перезапуск очищает все задачи.

Процесс завершения сигнализирует отмену и ждёт завершения потоков. Для нескольких ASGI-процессов или нескольких машин нужно внешнее хранилище задач и файлов и внешняя очередь; запуск `--workers 2` с текущей схемой не поддерживается. Сервис пока рассчитан на локальный сервер/одну машину, а не на публичный высоконагруженный хостинг.

## Обработка изображений и физика

Порядок слотов соответствует z = 24,1 / 25,3 / 26,5 / 27,7 мм. На вход можно отправить PNG/JPEG/WEBP/BMP/TIFF до 4 МиБ и 16 Мп каждый. Учитывается EXIF-поворот; прозрачность композится на чёрный фон; яркость преобразуется в один канал 8 бит. Пропорции сохраняются, размер доводится до 128×128 с чёрными полями.

В `neural/model.npz` лежит предварительная модель из эксперимента на одной фиксированной четвёрке; она используется только как начальная точка. Для пользовательского комплекта сервер отдельно настраивает обе матрицы MLP через градиент Френеля (обычно 600 шагов; доступны 0–2000). Ноль шагов — исключительно исходная модель, качество для новых изображений не подтверждено. Это подгонка под комплект, не доказательство обобщения обученной нейросети.

Loss: смесь нормированного MSE интенсивности, Pearson, Gaussian SSIM и остаточного рисунка других слоёв. Физические параметры не менялись: λ=532 нм, пиксел ПВМС=10 мкм, одна фазовая ДОЭ 128×128 на все плоскости. После настройки фаза сохраняется в PNG, этот файл повторно читается, а финальные восстановления выполняются ТЕКУЩИМ `simulator.simulate`, с физическим префактором и выходной фазой. Обучающий оператор имеет ту же нормированную интенсивность; согласованность проверяется тестом.

Для фото яркость восстановления масштабируется заранее определённым правилом: среднее равно среднему эталона. Pearson/SSIM/MSE считаются по финальным 8-битным PNG; unclipped метрики и физические float-интенсивности тоже включены в ZIP. В режиме готовой фазы сохранена прежняя нормировка PNG по максимуму. Без эталонов метрики сходства не выдумываются. Идеальное восстановление и отсутствие помех не гарантируются.

## API

- `GET /api/health` — состояние сервера и число активных/ожидающих задач.
- `POST /api/jobs/synthesis` — JSON `{images: [{name, data}, ...], steps: 600}`. Ровно четыре файла; `data` — base64 без префикса data URL.
- `POST /api/jobs/phase` — JSON `{kind: "png"|"txt", name, data}`.
- `GET /api/jobs/{id}` — состояние и ссылки на файлы готовой задачи.
- `POST /api/jobs/{id}/cancel` — запрос отмены.
- `WS /ws/jobs/{id}` — новые снимки состояния; после финального состояния соединение закрывается штатно.
- `GET /api/jobs/{id}/files/{filename}` — только файлы конкретной готовой задачи.

Оригинальные `/api/phases/*` и `/api/simulations/*` сохранены. Интерактивная документация FastAPI: `/docs`.

## Проверка

```powershell
python -m unittest discover -s tests -v
```

Тесты проверяют старую физику и GUI, загрузку фото и фазы, WebSocket, метрики, текстовую матрицу, совпадение физического оператора с обучающим, изоляцию параллельных задач, заполнение очереди, отмену и срок хранения. Настройка сервера не меняет пользовательские матрицы или исходные файлы проекта.
